# HoMoW Online · v6.8.0

## Вхід за логіном і паролем

На сторінці Render введи логін (3–24 латинські літери, цифри або _) та пароль (10–128 символів). Для нового персонажа натисни «Створити персонажа», надалі — «Увійти». Логін унікальний без урахування регістру та є ніком над персонажем. Персонаж і його прогрес прив’язані до серверного ID, а не значення з localStorage. На іншому ПК увійди тим самим логіном і паролем.

Більше не потрібні ChatGPT, popup, HOMOW_SERVER_URL чи налаштування Brukivka Cloud для гри. Хмарний акаунт у телефоні основної Бруківки залишається окремою системою і продовжує працювати як раніше. Його пароль не стає паролем HoMoW автоматично.

Вхід зберігається на 30 днів у HttpOnly + SameSite=Strict cookie (на HTTPS також Secure). У БД лише SHA-256 сесійних токенів і scrypt-хеші паролів з випадковими солями. Паролі не зберігаються у браузерному сховищі чи відкритим текстом у БД. «Вийти» відкликає поточну сесію і закриває підключення до світу. Повторне одночасне підключення одного персонажа відхиляється. Відновлення забутого пароля через email поки немає — збережи пароль у менеджері паролів.

## Збереження старого прогресу

Міграція accounts.sql лише додає таблиці та унікальний індекс, не видаляє персонажів. Ніки вже створених онлайн-персонажів зарезервовані: нова реєстрація не може забрати чужий нік або привласнити прогрес. Старий ChatGPT-акаунт не має пароля HoMoW автоматично. Для перенесення старого онлайн-персонажа на пароль треба окремо підтвердити його власника; не створюй замість нього дубль і не видаляй записи БД. Одиночні збереження не змінюються й не завантажуються на сервер.

## Render + Neon

Створи PostgreSQL базу (наприклад, Neon) та сервіс Render з репозиторію reformoti/Brukivka. Root Directory порожній; Runtime Node 22+; Build Command `npm ci && npm run build`; Start Command `npm start`; Health Check `/health`; для тестування можна вибрати Free.

У Render Environment встав підключення PostgreSQL у DATABASE_URL або DATABASE_URL_POOLED (pooled має пріоритет). Зберігай параметри TLS із рядка провайдера; не публікуй пароль. Для Render його публічний origin береться з RENDER_EXTERNAL_URL; власний домен потребує точного PUBLIC_ORIGIN. Секрети в .env/.env.local та .neon ігноруються Git. Схема персонажів і таблиці входу створюються сервером при запуску. Не вмикай горизонтальне масштабування: це один ігровий світ в одному процесі.

Для нового релізу: Manual Deploy → Clear build cache & deploy. Для входу відкрий саме HTTPS сторінку онлайн-сервісу Render. Одиночний homow.html у GitHub Pages залишається окремою грою.

## Що доступне

Спільна карта та монстри; WASD/стрілки — рух; пробіл — удар; R — прийом; Shift — ривок; Q — зілля. Сервер рахує переміщення, урон, нагороди, досвід і рівні. Ринок (E у таборі) містить усі товари, крафт, зачарування .1–.4 та продаж ресурсів в одній панелі. Поза табором E починає збір біля ресурсу. Спорядження й інструменти до T8, 16 видів монстрів. Дерево навичок, контракти, інвентар, карта, крафт, налаштування та музика тепер працюють через основний інтерфейс HoMoW. У меню є добровільні PvP-дуелі 1×1. Поки без чату та перенесення одиночного спорядження. Окремий онлайн-прогрес записується у PostgreSQL кожні 10 секунд, при відключенні й штатному SIGTERM. Аварійний збій може втратити останні 10 секунд; після перезапуску монстри починають із початкових спавнів. Ліміт 32 з’єднання — захист, а не гарантія продуктивності.

## Перевірки

`npm ci` — встановлення workspace-залежностей.
`npm run build` — імпорти ws/pg, синтаксис і симуляція.
`npm run test:online` — симуляція та HTTP/WebSocket-сценарії реєстрації, входу, унікальності ніків, cookie, руху, перезапуску й виходу. Для SQL інтеграційних тестів використано pg-mem; це не підтверджує підключення до реального Neon.
`npm start` — запуск із .env/.env.local.
`npm run test:db` — перевірка запису й відновлення тестового персонажа у реальному PostgreSQL в транзакції з ROLLBACK, після першого старту сервера.

## Один клієнт (v6.8.0)

Render віддає кореневий realms.html і його ресурси; homow-online.js лише підключає його до сервера. Окрему сторінку public/index.html та її client.js/market.js/style.css видалено. Існуючі cookies, акаунти, таблиця homow_players і серверні ID не змінюються. Після Manual Deploy → Deploy latest commit відкрий той самий Render URL. На GitHub Pages той самий інтерфейс залишається одиночним; кнопка Steam одразу відкриває офіційний сервер https://homow.onrender.com/. Музика й графічні налаштування локальні; онлайн-персонаж завантажується тільки із серверної бази. Меню та пауза зупиняють керування персонажем, а не весь спільний світ.

## Steam та PvP (v6.8.0)

Steam → HoMoW → Грати одразу відкриває офіційний сервер https://homow.onrender.com/. Введення адреси, попереднє повернення з гри та налаштування сервера більше не потрібні. Старі локальні значення адреси ігноруються (v6.8.1).

Меню → Бій з гравцями → Знайти суперника. Черга доступна в таборі; обидва учасники погоджуються входом у чергу. Окрема арена ізольована від PvE та інших дуелей. До 120 секунд, без нагород сріблом або втрати спорядження. HP/мана та позиція до дуелі відновлюються; зілля в дуелі не витрачаються. Вихід або здача завершує дуель на користь суперника, аварійне збереження повертає персонажа до попереднього місця. PvP-перемоги зберігаються у персонажі.
