# HoMoW Online Alpha · запуск на Render

Підготовлено сервер і окремий онлайн-клієнт. Це перша кооперативна версія: спільна карта й монстри, рух WASD, удари/прийоми/ривок/зілля, серверні нагороди, досвід і рівні. Над персонажем — підтверджений нік існуючого Brukivka Cloud акаунта. Без входу сервер не додає гравця до світу. Другий одночасний вхід тим самим акаунтом відхиляється.

Поки немає онлайн-ринку, крафту, дерева навичок, PvP, чату та перенесення одиночної екіпіровки. Одиночний HoMoW продовжує працювати без змін. Онлайн-прогрес окремий: локальні JSON/баланси не приймаються сервером.

## 1. Постійна база PostgreSQL

Створи базу PostgreSQL у провайдера з відповідним безкоштовним тарифом, наприклад Neon, та отримай рядок підключення. Збережи параметри TLS із виданого рядка. Не публікуй пароль або рядок у GitHub чи чаті: встав його в секретну змінну Render `DATABASE_URL`. Не використовуй тимчасовий диск Render як збереження персонажів. Без бази сервер навмисно не запускається.

## 2. Сервіс Render

У Dashboard: **New → Blueprint** → підключи репозиторій `reformoti/Brukivka` → використай кореневий `render.yaml`. Перевір план **Free**. У запитаній змінній `DATABASE_URL` встав підключення PostgreSQL. Запусти розгортання.

Якщо створюєш вручну: New → Web Service; репозиторій `reformoti/Brukivka`; гілка `main`; Runtime Node; Root Directory залиш порожнім (сервер імпортує спільні модулі гри); Build Command `cd homow-server && npm ci`; Start Command `cd homow-server && npm start`; Health Check `/health`; план Free. `PORT` і `RENDER_EXTERNAL_URL` Render задає автоматично. Власний домен потребує змінної `PUBLIC_ORIGIN` з точним HTTPS origin і відповідного дозволу в сервісі акаунтів.

## 3. Зв’язок із акаунтами — після отримання адреси

Надішли лише публічну адресу `https://ім’я.onrender.com`. У вже наявному Brukivka Cloud потрібно встановити серверну змінну `HOMOW_SERVER_URL` на цей точний HTTPS origin (без шляху), після чого опублікувати конфігурацію. Код сервісу акаунтів і міграція `0002_previous_madripoor` вже підготовлені. До цього вхід повертає «Онлайн-сервер ще не підключено», а не відкриває гру без авторизації. Потім можна додати онлайн-кнопку в Steam.

Сервіс акаунтів має дозволяти доступ друзям; кожен входить власним акаунтом ChatGPT і обирає власний унікальний нік. Авторизація не ґрунтується на локальному профілі браузера.

## Як працює вхід

Popup відкриває Brukivka Cloud. Авторизований користувач отримує випадковий 256-бітний код на 60 секунд, прив’язаний до конкретного Render origin. У D1 зберігається лише SHA-256 коду. Браузер передає його по WSS; ігровий сервер погашає код по HTTPS. Атомарний DELETE RETURNING у D1 дозволяє використати код лише раз. Нік та ідентифікатор повертає сервіс акаунтів, клієнт їх не задає. Коди не потрапляють у URL чи localStorage. Повторний popup після першого SSO-входу може знадобитися, якщо браузер розірвав opener.

## Збереження та обмеження

Персонаж записується в PostgreSQL кожні 10 секунд, при відключенні й штатному SIGTERM. Різкі збої можуть втратити останні 10 секунд; аварійно незбережений прогрес не гарантується. Сервери Free можуть засинати, перезапускатися, вичерпувати ліміти; перший вхід після сну повільніший. Живий стан монстрів після перезапуску відновлюється з початкових спавнів, персонажі — із бази. На першу версію встановлено ліміт 32 з’єднання; це захисний ліміт, а не обіцянка продуктивності для 32 активних гравців. Один екземпляр сервера; не вмикай горизонтальне масштабування без винесення світу й блокування сесій у спільне сховище.

Перевірка після запуску: два акаунти у двох браузерах; видно ніки та рух; обоє бачать загибель одного монстра; повторний вхід тим самим акаунтом відхиляється; після перепідключення зберігаються рівень/срібло/позиція; після Render Restart персонаж відновлюється. До створення сервісу й бази ця перевірка не виконана.

## Локальна перевірка

`node --test homow-server/test.mjs`

`cd homow-server && npm ci && DATABASE_URL='<локальне підключення>' npm start`

Локальний клієнт: http://localhost:3000. Продукційний issuer навмисно не дозволяє localhost; для повного локального входу потрібен окремий тестовий issuer. У коді немає обхідного входу або тестового пароля для production.
