# HoMoW Online · v6.10.0

## Вхід за логіном і паролем

На сторінці Render введи логін (3–24 латинські літери, цифри або _) та пароль (6–128 символів). Для нового персонажа натисни «Створити персонажа», надалі — «Увійти». Логін унікальний без урахування регістру та є ніком над персонажем. Персонаж і його прогрес прив’язані до серверного ID, а не значення з localStorage. На іншому ПК увійди тим самим логіном і паролем.

Більше не потрібні ChatGPT, popup, HOMOW_SERVER_URL чи налаштування Brukivka Cloud для гри. Хмарний акаунт у телефоні основної Бруківки залишається окремою системою і продовжує працювати як раніше. Його пароль не стає паролем HoMoW автоматично.

Вхід зберігається на 30 днів у HttpOnly + SameSite=Strict cookie (на HTTPS також Secure). У БД лише SHA-256 сесійних токенів і scrypt-хеші паролів з випадковими солями. Паролі не зберігаються у браузерному сховищі чи відкритим текстом у БД. Налаштування → «Вийти з акаунта» відкликає поточну сесію і закриває підключення до світу. Повторне одночасне підключення одного персонажа відхиляється. Відновлення забутого пароля через email поки немає — збережи пароль у менеджері паролів.

## Збереження старого прогресу

Міграція accounts.sql лише додає таблиці та унікальний індекс, не видаляє персонажів. Ніки вже створених онлайн-персонажів зарезервовані: нова реєстрація не може забрати чужий нік або привласнити прогрес. Старий ChatGPT-акаунт не має пароля HoMoW автоматично. Для перенесення старого онлайн-персонажа на пароль треба окремо підтвердити його власника; не створюй замість нього дубль і не видаляй записи БД. Одиночні збереження не змінюються й не завантажуються на сервер.

## Render + Neon

Створи PostgreSQL базу (наприклад, Neon) та сервіс Render з репозиторію reformoti/Brukivka. Root Directory порожній; Runtime Node 22+; Build Command `npm ci && npm run build`; Start Command `npm start`; Health Check `/health`; для тестування можна вибрати Free.

У Render Environment встав підключення PostgreSQL у DATABASE_URL або DATABASE_URL_POOLED (pooled має пріоритет). Зберігай параметри TLS із рядка провайдера; не публікуй пароль. Для Render його публічний origin береться з RENDER_EXTERNAL_URL; власний домен потребує точного PUBLIC_ORIGIN. Секрети в .env/.env.local та .neon ігноруються Git. Схема персонажів і таблиці входу створюються сервером при запуску. Не вмикай горизонтальне масштабування: це один ігровий світ в одному процесі.

Для нового релізу: Manual Deploy → Clear build cache & deploy. Для входу відкрий саме HTTPS сторінку онлайн-сервісу Render. Одиночний homow.html у GitHub Pages залишається окремою грою.

## Що доступне

Спільна карта та монстри; WASD/стрілки — рух; пробіл — удар; R — прийом; Shift — ривок; Q — зілля. Сервер рахує переміщення, урон, нагороди, досвід і рівні. Торговці села (E поруч або клік на NPC) мають окремі спеціалізації, крафт, зачарування .1–.4 та ринок для продажу ресурсів. Поза табором E починає збір біля ресурсу. Спорядження й інструменти до T8, 16 видів монстрів. Дерево навичок, контракти, інвентар, карта, крафт, налаштування та музика тепер працюють через основний інтерфейс HoMoW. Кнопка ⚔ перемикає добровільний PvP у спільному світі. Поки без чату та перенесення одиночного спорядження. Окремий онлайн-прогрес записується у PostgreSQL кожні 10 секунд, при відключенні й штатному SIGTERM. Аварійний збій може втратити останні 10 секунд; після перезапуску монстри починають із початкових спавнів. Ліміт 32 з’єднання — захист, а не гарантія продуктивності.

## Перевірки

`npm ci` — встановлення workspace-залежностей.
`npm run build` — імпорти ws/pg, синтаксис і симуляція.
`npm run test:online` — симуляція та HTTP/WebSocket-сценарії реєстрації, входу, унікальності ніків, cookie, руху, перезапуску й виходу. Для SQL інтеграційних тестів використано pg-mem; це не підтверджує підключення до реального Neon.
`npm start` — запуск із .env/.env.local.
`npm run test:db` — перевірка запису й відновлення тестового персонажа у реальному PostgreSQL в транзакції з ROLLBACK, після першого старту сервера.

## Один клієнт (v6.8.0)

Render віддає кореневий realms.html і його ресурси; homow-online.js лише підключає його до сервера. Окрему сторінку public/index.html та її client.js/market.js/style.css видалено. Існуючі cookies, акаунти, таблиця homow_players і серверні ID не змінюються. Після Manual Deploy → Deploy latest commit відкрий той самий Render URL. На GitHub Pages той самий інтерфейс залишається одиночним; кнопка Steam одразу відкриває офіційний сервер https://homow.onrender.com/. Музика й графічні налаштування локальні; онлайн-персонаж завантажується тільки із серверної бази. Меню та пауза зупиняють керування персонажем, а не весь спільний світ.

## Steam та PvP (v6.8.0)

Steam → HoMoW → Грати одразу відкриває офіційний сервер https://homow.onrender.com/. Введення адреси, попереднє повернення з гри та налаштування сервера більше не потрібні. Старі локальні значення адреси ігноруються (v6.8.1).

Кнопка ⚔ у меню відразу вмикає або вимикає PvP. Ворогом може бути лише інший гравець із увімкненим режимом, і обидва мають перебувати поза селом. Немає черги, телепортації та окремої арени. Клік обирає ціль, пробіл атакує, R застосовує прийом. Урон, дальність, перешкоди й згода перевіряються сервером при влучанні. Режим не можна вимкнути 10 секунд після останнього PvP-влучання. Поразка повертає в село з 65% HP без втрати срібла чи спорядження; PvP вимикається. Зілля витрачаються як у звичайному світі. Після нового входу PvP вимкнено, попередні PvP-перемоги збережено.

## Торговці табору (v6.9.0)

Коваль продає та створює зброю, лати й інструменти; маг — посохи та магічні речі. Рунний майстер зачаровує придбане спорядження до .4; бронник продає захист. Алхімік продає й створює зілля, ремісник переробляє матеріали, інтендант приймає ресурси до сховища й видає контракти. Ринок купує ресурси із сумки або сховища. Кількість і сума продажу видимі перед дією. NPC відкриваються кліком або E поруч у таборі; вкладки дозволяють перейти до іншого торговця.

## Село, рівні та музика (v6.10.0)

Зона спавна — село 880 × 780 з домом для кожного торговця, фізичними стінами, воротами на сході та двома стражниками. Тут не діє урон мобів або PvP. Старі персонажі з координатами всередині нового будинку переміщуються на безпечний спавн без втрати речей, рівня або валют.

Слиз має Lv 1, вовк Lv 3, Прадавній охоронець Lv 20, Крижаний велетень Lv 25. Різниця рівнів рахується окремо для кожного гравця: проти Lv 1 вовк б’є на 70 до захисту, а стартовий удар 27 знімає лише 6 HP. Проти Lv 3 базовий удар вовка — 32. Ціль для Lv 2: 180 XP, тобто 10 слизнів без бонусів; надалі вимоги зростають. Слабкі вороги дають менше досвіду, сильніші — більше; рівень і нагорода показані над ціллю, подробиці сховані в налаштуваннях.

Налаштування музики використовують music-catalog.js і всі music/mp3(1).mp3 … mp3(10).mp3. Перший жест запускає звук згідно з обмеженнями браузера. Можна вибрати трек, змінити гучність, зупинити та перейти до наступного; кінець треку запускає наступний автоматично. Render підтримує запити Range для аудіо. Самостійний HTML містить код і графіку, але MP3 бере з GitHub Pages при відкритті як file://, тому для музики потрібна мережа; онлайн-версія використовує ті самі файли на своєму сервері.

Перевірки включають два реальні WebSocket-підключення з парольними сесіями, взаємну згоду PvP, захист села, бойові вміння, крива XP, усі 10 аудіофайлів через HTTP Range та основний і самостійний клієнти. SQL інтеграція використовує pg-mem.
