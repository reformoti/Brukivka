# HoMoW 6.33.3: передача и производительность

В репозитории сохранены все исходные модули, стили, шрифты, ассеты и механики.
`homow.html` по-прежнему собирается командой `python scripts/build-homow.py` и открывается локально без отдельного сервера. Прежний ключ сохранения `brukivka_realms_v1` не изменён.

## Что изменено

- Цикл Canvas прекращает работу в скрытой вкладке, сразу отправляет остановку ввода онлайн-серверу и сохраняет одиночную игру. Возврат запускает один цикл без симуляции прошедшего в фоне времени. Восстановление страницы из back/forward cache также запускает цикл.
- Ограничение 30/45/60 FPS учитывает остаток времени: небольшая погрешность vsync больше не пропускает лишние кадры. Шаг симуляции, предел накопленного времени, физика, бои и серверные 20 тиков/с сохранены. Это исправление планирования, а не гарантия 60 FPS на любом устройстве.
- Записи видимых объектов переиспользуются через WeakMap; они не удерживают удалённых монстров/предметы. Градиент виньетки пересоздаётся после изменения размеров Canvas, числовой формат — после смены языка. Слои, порядок сортировки, качество, анимации и ассеты сохранены.
- Node читает неизменённые публичные файлы из ограниченного LRU-кэша: максимум 64 записи / 8 MiB суммарно для исходных и сжатых вариантов, плюс одна постоянная публичная HTML-оболочка. Изменение файла проверяется через stat. Одновременные запросы разделяют чтение/сжатие.
- Публичные HTML поддерживают ETag / Last-Modified / 304, Gzip / Brotli и HEAD. Только статические ресурсы с текущим `?v=` получают годовой immutable-кэш. HTML и неверсионированные ресурсы проходят проверку актуальности. `Vary: Accept-Encoding` разделяет варианты.
- Авторизация, API, `/online-config.js`, health/config и приватные данные остаются `no-store`. WebSocket-сообщения, частота симуляции и сохранения в БД не изменены. Service Worker не устанавливается: обновления и вход продолжают работать через обычное HTTP-кэширование.

## Измерения

Для точного HTML этого релиза, без удаления контента:

| Представление | Байт | Снижение относительно несжатого HTML |
| --- | ---: | ---: |
| Исходный HTML | 775 841 | — |
| Gzip level 9, предсжатый файл | 262 369 | 66,18% |
| Brotli quality 11, предсжатый файл | 219 158 | 71,75% |

`npm run build:transfer` создал 45 пар lossless-вариантов и проверил каждую распаковкой с побайтовым сравнением. Файлы `.gz`/`.br` не заменяют оригиналы и не коммитятся.
Node сжимает публичные ответы один раз на закэшированную версию, используя более быстрые уровни Gzip 6 / Brotli 5. Их размеры могут отличаться от таблицы. Nginx с предсжатыми файлами вообще не тратит CPU Node на их передачу.
Повторный запрос с действительным ETag получает 304 без тела; заголовки всё равно передаются. Версионированная статика в свежем браузерном кэше не запрашивается заново. Эти цифры не описывают трафик игрового WebSocket, музыку, авторизацию или нагрузку БД.

Проверены 233 игровых теста и 60 тестов клиента/сервера без сетевых сокетов, включая настоящий HTTP-обработчик с mock request/response, работу сохранений, онлайн-вход, панели, компрессию, 304, HEAD, кэш и ограничения FPS. Дополнительно сравнены 20 шагов полного клиента до/после: состояния сохранений и порядок рисуемых надписей совпали. Проверены остановка/возврат RAF и сборка как исходной страницы, так и автономного HTML. Nginx и реальный VPS в этой среде не запускались; FPS на пользовательском устройстве и процент загрузки VPS не измерены.

## Что сделать на VPS

Текущая опубликованная игра использует GitHub Pages. Настройки ниже применяются к собственному VPS; GitHub Pages не читает конфигурацию Nginx из репозитория.

1. Обновить checkout этого репозитория в `/var/www/brukivka` (или использовать свой путь).
2. Сгенерировать варианты рядом с оригиналами:
   ```sh
   python scripts/build-homow.py
   npm run build:transfer
   ```
3. Скопировать `deploy/nginx/homow.conf.example` в конфигурацию своего Nginx. Подставить реальный домен, путь checkout и существующий TLS-сертификат. В `http {}` должны быть подключены стандартные `mime.types`. Пример использует Nginx >=1.25.1 с HTTP/2; для старой версии в файле указан синтаксис `listen ... http2`.
4. По умолчанию выбран автономный HTML: для него не нужны Node, PostgreSQL и игровой сервер. Для прежнего онлайн-режима заменить только три HTML-location блоком из `homow-online.locations.conf.example`, задать `PUBLIC_ORIGIN=https://ваш-домен` и перезапустить существующий Node-сервис после обновления. Не подменять онлайн-маршрут сырым автономным HTML: это другой режим сохранения.
5. `gzip_static` требует модуль `http_gzip_static_module`; проверить `nginx -V`. Brotli опционален: включать `brotli_static on` только при установленном ngx_brotli. Без Brotli остаётся Gzip, без gzip_static можно закомментировать эту директиву и оставить обычный Gzip.
6. Проверить и применить:
   ```sh
   sudo nginx -t
   sudo systemctl reload nginx
   curl -I -H 'Accept-Encoding: gzip' https://ваш-домен/homow.html
   ```
   Ожидаются `Content-Encoding: gzip`, `Vary: Accept-Encoding`, ETag и Cache-Control с перепроверкой HTML. Повторить запрос с возвращённым `If-None-Match`: ответ должен быть 304. API должен возвращать `Cache-Control: no-store`. Для Brotli аналогично проверить `Accept-Encoding: br`.

Обновления выкладывать целиком и атомарно: исходные файлы, свежие `.gz`/`.br`, затем reload/restart. Не переносить старые сжатые варианты поверх нового HTML. Старые сохранения и базы не удалять.

Документация: [gzip](https://nginx.org/en/docs/http/ngx_http_gzip_module.html), [gzip_static](https://nginx.org/en/docs/http/ngx_http_gzip_static_module.html), [Cache-Control](https://nginx.org/en/docs/http/ngx_http_headers_module.html), [HTTP/2](https://nginx.org/en/docs/http/ngx_http_v2_module.html), [ngx_brotli](https://github.com/google/ngx_brotli).
