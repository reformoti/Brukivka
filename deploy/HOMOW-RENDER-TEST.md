# Новый тестовый проект HoMoW: Render + Neon

Конфигурация: [`render-test.yaml`](../render-test.yaml). Она создаёт отдельный проект **HoMoW Test 2026-11-15**, окружение **Testing** и бесплатный сервис **homow-test-20261115** во Frankfurt. Старый `render.yaml`, сервис `homow-online` и существующие базы не изменяются.

1. В Neon создать новый тестовый проект/базу рядом с Frankfurt. Это пустой онлайн-мир; старая база и браузерные сохранения остаются на месте. Скопировать pooled connection string через защищённое поле настройки хостинга. Строку подключения не добавлять в GitHub или переписку.
2. В Render создать новый Blueprint из `reformoti/Brukivka`, ветка `main`, Blueprint Path `render-test.yaml`. Сначала убедиться, что это отдельный новый проект, а не существующий Blueprint старого сервиса. Задать `DATABASE_URL_POOLED` из нового проекта Neon. Не добавлять старый DATABASE_URL или DATABASE_URL_POOLED через общий environment group.
3. Root Directory пустой; Node 24; Build `npm ci && npm run build`; Start `npm start`; Health Check `/health`. Платный тариф и диск для теста не требуются. Автодеплой выключен, чтобы изменения основной игры не расходовали сборки нового сервиса без необходимости. Первый деплой запускается при создании.
4. Дождаться успешного деплоя и проверить фактический HTTPS URL, который вернёт Render. Не угадывать его по имени сервиса. `/health` должен вернуть `ok: true`; `/config` — `client: canonical-homow`. `PUBLIC_ORIGIN` берётся из RENDER_EXTERNAL_URL, фиксировать старый адрес нельзя.
5. Открыть корень нового сервиса, создать тестового персонажа, войти, проверить движение/панели/музыку, перезагрузить страницу и повторно войти. Должен загрузиться тот же онлайн-персонаж. Проверка записи/чтения БД: `npm run test:db` после первого запуска сервера, без публикации строки подключения.
6. После успешной проверки можно переключить запуск HoMoW из Steam на фактический новый URL. До этого Steam продолжает открывать рабочий автономный HTML. `homow.html` в репозитории остаётся доступен.

На Render вручную устанавливать Nginx не нужно: публичные ответы уже сжимаются сервером, TLS и входящий прокси обеспечивает Render. Примеры Nginx из другой инструкции предназначены для собственного VPS.

Free Render засыпает после простоя; первое открытие может ждать пробуждения. Лимиты трафика и часов относятся к workspace: новый проект не обнуляет исчерпанную квоту. При ограничении workspace сначала проверить его состояние, не включать платный тариф автоматически.

## Состояние подготовки

Файлы готовы к созданию ресурсов. Реальные ID нового Render-сервиса, URL и Neon-проекта добавляются только после их создания и проверки. Эта инструкция сама по себе не подтверждает развёртывание.
