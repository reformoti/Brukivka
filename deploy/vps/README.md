# HoMoW на бесплатной Oracle VM

Онлайн-сервер развёрнут 15 ноября 2026 года: https://homow.92-5-85-199.sslip.io/ . Oracle VM `homow-free`, Франкфурт AD-1, Ubuntu 24.04 ARM, 1 OCPU / 6 GB RAM, стандартный boot volume около 47 GB. Используется отдельная тестовая база Neon `homow_test`. Render для этого хоста не нужен. Механики, протокол WebSocket, ассеты и локальный HTML не менялись.

Адрес на sslip.io — временный адрес для проверки, привязанный к публичному IP VM. Перед сменой IP или домена обновить DNS, сертификат, Nginx и `PUBLIC_ORIGIN`, затем пересоздать контейнер. Переход из Steam пока сохраняет существующую автономную версию; онлайн-игра открывается по ссылке выше.

## Аккаунт и VM

Пользователь самостоятельно регистрируется на https://www.oracle.com/cloud/free/ и проходит проверку личности/карты. Бесплатный тариф не является обещанием вечного uptime: Oracle может отозвать простаивающую VM; доступность ресурсов зависит от региона.

В консоли выбирать только **Always Free Eligible**: Ubuntu и `VM.Standard.A1.Flex`, суммарно не более 2 OCPU / 12 GB RAM и не более 200 GB Always Free block storage в домашнем регионе по текущим условиям. Минимальный boot volume около 47–50 GB достаточен для приложения. Временный trial-кредит не использовать для платных VM, дисков или других ресурсов. Параметры и отметку Free повторно проверить в консоли перед созданием.

## Запуск после получения VM

1. Установить Docker Engine + Compose plugin, Nginx и Git из официальных репозиториев для выбранного Ubuntu; Docker образ поддерживает AMD64 и ARM64 через официальный `node:24-bookworm-slim`.
2. Клонировать `https://github.com/reformoti/Brukivka` в `/var/www/brukivka`.
3. Скопировать `deploy/vps/.env.example` в `deploy/vps/.env`; задать строку **новой тестовой** Neon БД и реальный HTTPS `PUBLIC_ORIGIN`. Ограничить доступ к файлу: `chmod 600 deploy/vps/.env`. Секреты не отправлять в GitHub/переписку.
4. Из корня репозитория:
   ```sh
   sudo docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yaml up -d --build
   sudo docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yaml ps
   curl -f http://127.0.0.1:3000/health
   ```
5. На действующем хосте Nginx проксирует запросы в Node на localhost:3000 с поддержкой WebSocket; белый список публичных файлов, сжатие и кеширование выполняет существующий `homow-server/static.mjs`. Для альтернативной раздачи статики через Nginx использовать `deploy/nginx/homow.conf.example`, заменив три HTML-location онлайн-блоком из `homow-online.locations.conf.example`. Указать действительные домен, TLS-сертификат и путь репозитория. В Oracle security list и firewall открыты 80/443; SSH использует ключ. Порт 3000 наружу не открывать. При настройке постоянного доступа ограничить SSH доверенными адресами.
6. Выполнить `nginx -t`, затем reload Nginx. Проверить HTTPS, регистрацию тестового персонажа, вход, сохранение и восстановление после reload. Переключать Steam на фактический URL только после этой проверки. Не угадывать IP или домен заранее.

Для формирования предсжатых файлов на хосте без Node:
```sh
sudo docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yaml run --rm --no-deps --user "$(id -u):$(id -g)" -v "$PWD:/transfer" -w /transfer game node scripts/precompress-homow.mjs
```
Это создаёт `.gz`/`.br` рядом с исходными публичными файлами. Их нужно обновлять при каждом релизе. Команда не выводит секреты.

## Обновление и проверка

```sh
cd /var/www/brukivka
git pull --ff-only
sudo docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yaml up -d --build
sudo docker compose --env-file deploy/vps/.env -f deploy/vps/compose.yaml ps
curl -fsS https://homow.92-5-85-199.sslip.io/health
```

Сервер запускается от непривилегированного пользователя, получает SIGTERM напрямую через init и имеет 60 секунд на сохранение. Контейнер перезапускается после сбоя/перезагрузки VM; PostgreSQL-прогресс находится в Neon. Логи ограничены 3 файлами по 10 MB. Docker-сборка не включает `.env`, `.neon`, локальные зависимости или Git-метаданные.

На реальной VM проверены: Docker-сборка ARM64, статус healthy, Nginx, HTTP → HTTPS, регистрация, вход, Secure / HttpOnly cookie, WebSocket, запись персонажа в Neon, сохранение сессии и восстановление персонажа после перезапуска контейнера. В браузере открывается канонический интерфейс HoMoW с формой входа, ошибок консоли не обнаружено. Создан один отдельный технический персонаж `deploycheck_*`; его сессия закрыта после проверки.

Сертификат Let's Encrypt установлен Certbot, автоматическое продление настроено системным таймером. Принятие условий подтверждено владельцем. Ключи, пароли, `.env` и сертификаты в репозиторий не добавляются. Старые проекты Neon и Render не изменялись.

## Диагностика кадров и сети

В версии 6.33.7 сглажены собственный персонаж и камера между серверными пакетами; авторитетное состояние не интерполируется и не меняется. Визуальный час анимаций обновляется каждый кадр. Резкие телепортации отображаются сразу.

Для измерения открыть игру с `?perf=1`. Только в этом режиме создаётся скрытый `output#homowPerformance` с JSON в `data-stats`: FPS нарисованных кадров, частота callback браузера (`rafFps`), 95-й перцентиль интервала кадра и времени отрисовки, число пауз свыше 50 мс, размеры Canvas, качество и последнее измерение RTT WebSocket. Фоновые периоды и открытые игровые панели не входят в замер. Выборка ограничена 3600 кадрами; это диагностика, а не обещание FPS на любом устройстве.

При проверке 15 ноября в Chrome, high, Canvas 1367×590, в деревне до исправления ограничителя наблюдалось около 27–30 FPS. После исправления первый активный интервал дал 58,2 FPS при такой же частоте callback браузера и 4,4 мс p95 отрисовки. При более длительном наблюдении частота callback тоже снижалась; стабильные 60 FPS во всех условиях этим тестом не подтверждены. RTT из браузера был около 31 мс в спокойном интервале, с отдельными скачками почти до 300 мс. Моментальный снимок контейнера с одним игроком: около 1% CPU и 31 MiB RAM. Это не нагрузочный тест множества игроков и не измерение всех боевых сцен.

В 6.33.8 исправлен статус поля команд в настройках. Дополнительный замер в активном окне дал около 47 FPS при 47,6 callback/с и 3,4 мс p95 отрисовки; последнее измерение RTT доходило до 950 мс (включает планирование обработчика ответа в браузере). Причина всех оставшихся пауз одним этим замером не установлена. Наличие сглаживания не означает устранение сетевых задержек или ограничений браузера.
